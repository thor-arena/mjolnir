## The two re-adaptations (context-only)

Both broke on an upstream **repo-wide docstring reformat**, no semantic
drift in the touched regions (`_annotate_eagle_groups` already gates on
`use_eagle_block_drop()` in both bases):

1. **55390 hunk #3** (`use_deepseek_v4_fallback` → `use_trailing_layer_fallback`
   docstring rename): 0.30.0 re-indented the `_annotate_eagle_groups`
   `Args:` block from 4/8 to 8/12 spaces and dropped the trailing blank line
   before the closing `"""`. Context re-adapted to the new indentation;
   lands with fuzz 1; post-patch docstring verified byte-exact.
2. **55519 hunk #1** (warning gate `use_eagle()` → `use_eagle_block_drop()` +
   docstring paragraph): 0.30.0 dropped the trailing blank line in
   `_warn_if_unannotated_eagle_mamba`'s docstring. Context re-adapted;
   lands clean.

Lesson for future bumps: a formatter pass (docstring reflow) can break
hunks whose *context* is docstring text even when the code is untouched —
check the `.rej` context lines before assuming semantic drift.
